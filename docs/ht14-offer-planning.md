# HT14 — Explainable local price and offer planning

Cost scope committed before implementation: docs/ht14-cost-review.md, commit413a2b676cc52d6cb0bb530ccd9706fb3959e1b0. This is a rule-based planner inside the existing Funnels page, beside existing AI drafting, not another generator or provider call. It uses catalog cards/index/candidates already read by that page. Category sets are computed once; no extra product/history/service read.

Only confirmed positive-price, published one-off products without options or bundle/call/recurring status are considered. Course and other one-off items are kept in separate coarse groups. The lower-middle price of other eligible items in the same group is an existing observed catalog price, even for an even-sized sample. With no comparable item, the reference stays at the selected product’s current price. The sample count, rule and observed range are shown, with the explicit limit that different content may have different value. No outside benchmark, sales projection, willingness-to-pay inference or profit claim.

The review structure uses an existing product page/checkout/delivery checklist. One optional after-payment candidate is suggested only from existing eligible offer candidates when actual Stripe/payment and tax settings permit one-click offers; otherwise the unavailable condition is explicit. Gates, consent, page permissions, actual configuration and buyer terms still need review. The local planner never enables a payment route, changes a merchant/platform price or modifies an existing funnel.

Accept creates an editable unsaved local text plan. Reject/discard changes only this page’s proposal. Copy is an explicit local clipboard action; the existing product editor link remains available. The shared leave guard protects an accepted unsaved plan. Nothing is saved/published/activated/sent, and no AI request runs. Existing AI pool/caps/reserve, visible limits, identifiers, creator content and buyer languages remain untouched. PLANS_ON_SALE=false and all financial/commercial/permission/opt-in gates remain binding. No new operational cost or entitlement; the zero-delta sizing assessment is not overall margin certification.

Tests: same-category observed-price selection, actual lower-middle reference, invalid/hidden/other-category exclusion, current-price fallback, source immutability and unavailable one-click permissions; synthetic390/1280 accept/reject/edit/discard, declared rules/conditions, no writes/AI, width and AA. Full repository CI including controlled mobile measurements required at the final head; READY/domain/exact version before a functional publication. No real account, payment, external message or submission.
