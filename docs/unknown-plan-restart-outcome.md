# Unknown plan restart outcome notice

AB(a), 2026-10-24. After the existing provider-retry horizon, a network or provider error does not prove that no charge occurred. Those outcomes now receive a separate plain US English notice stating uncertainty, directing the creator to billing and asking them to contact support before starting again. It asks only for charge date/amount and explicitly excludes card details. The existing bank/card-decline notice remains for that classified case.

The synthetic regression forces the existing provider stub to stay unavailable beyond the retry horizon and checks the unconfirmed subject, explicit uncertainty, checking before another restart, absence of a no-charge claim and absence of a taking-payments claim. Existing normal restart/card/customer, once-only notices, retry and decline cases remain.

This changes only which existing notice is selected. It adds no send, provider request, Redis operation, field or key. Template bytes and branch CPU are unmeasured, not certified zero; all monthly/annual worst-case plan costs, highest-paid assumptions, spend floor, caps/reserves, most onerous taxes and all LLC fixed costs including preserved Hazelsong residuals remain binding. No 60% margin is certified. Policies remain null, coverage false and sales closed.

Durable pre-charge intent, prevention of duplicates beyond provider idempotency retention, funded restart and persistence reconciliation remain unfinished. This notice does not solve those gaps or assert whether an uncertain charge succeeded. Full remote CI on the new head is mandatory. Tests are synthetic; no real email, payment or provider action is performed.
