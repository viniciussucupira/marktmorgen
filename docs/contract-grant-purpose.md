# A funding grant keeps its reserved purpose

AB(a), 24 October 2026. This is an internal admission correction, not completion of the commercial opening block.

The permanent cash receipt already records either checkout or switch. The returned server grant now carries that same action, and the billing caller must match it before any provider read or write. A switch grant cannot open a new enrollment; a checkout grant cannot change an existing plan. Missing and unknown actions refuse as well. This does not authenticate a forged JavaScript object or replace the durable cash receipt.

The customer-recovery Checkout retry now rechecks the same submission window before its second POST. A slow price lookup before a switch also cannot write pending-funding metadata after that window. No new retry, provider call, key, field in permanent storage, price, visible entitlement or supplier is introduced.

## Synthetic verification

The existing remote suite checks:
- returned checkout and switch actions match the corresponding permanent receipt;
- both crossed purposes, missing action and unknown action make zero provider requests;
- a simulated customer error followed by an expired grant makes only the first Checkout POST;
- a simulated slow price lookup makes no pending-metadata or subscription update;
- correctly funded Checkout and pending switch behavior still work.

All provider traffic in these tests is intercepted. Full checks on the exact combined head are required before incorporation. An isolated passing job is insufficient.
