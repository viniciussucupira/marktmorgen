# HT9 — Sales lever settings beside measured evidence
The existing /studio/growth guide links permitted stats readers to a Grow your sales section in the main studio. It reuses the loaded store and the existing readSales payment ledger. No new provider, Redis query, event table or automatic action.

Six rows: order bump, upsell, downsell, bundle, checkout recovery and next offer. Saved configuration is distinguished from operational availability. Product-head limitations are explicit; a funnel flag does not prove a downsell path exists.
Existing paid records are grouped without another read:30 UTC days, same store currency only, complete ledger required for amounts. Tagged bump/bundle/recovered checkouts show whole-payment gross, not an invented separately paid item amount or incremental effect. After-checkout offer payments combine upsells and downsells because existing metadata does not identify historical decline paths separately. Downsell-only and next-offer-only amounts remain unknown. No tags/partial records is unknown attribution, never a certified zero. Rows overlap and cannot be added. Refunds, fees, taxes and all other costs remain outside these gross figures, explicitly disclosed.

Cost-free optional mechanisms already become available when the creator configures real products/terms; there is no new global switch to enable or missing product/price to invent. Buyer acceptance remains explicit. Existing creator opt-outs, permissions and content are preserved. Recovery needs sending/consent/cost allowances; next offer uses the paid Store assistant add-on/read budget/AI reservation. Neither is enabled automatically. Unknown cost is not treated as zero.
The section changes no setting and cannot open sales. M0/tax/art9a/commercial, PLANS_ON_SALE=false, prices, caps and persisted identifiers stay unchanged.
Unit cases: actual tagged payments, currency exclusion, unknown attribution, incomplete ledger and immutable settings. Browser390/1280: six rows, truthful scope, no activation controls/writes, keyboard/axe/width. Existing synthetic fixture only; no real provider/account/payment/message. Full final-head CI and ordered publication required.
