## What the actual code does

lib/company-margin-report.ts applies the existing commercialProfitMixData boundary to the original input before any copy or canonical snapshot, including inspection of the held-store observation. It then validates the detached accounting data with commercialProfitMix. The shared boundary checks every original container with Node's native Proxy detector before reading own data descriptors; no untrusted graph is cloned, no getter or Proxy trap executes, and runtimes without that native proof remain unknown. Proxies, revoked proxies, inherited/accessor fields and extra root or source-row categories remain unknown, never complete. All nine revenue sources, full company fixed-cost reconciliation, all variable costs, taxes, refunds and reserves are required. Only reconciled_actual inputs for the previous complete UTC calendar month are accepted. A forecast, annual snapshot, other month, missing source/category/evidence, unsafe amount or allocation mismatch produces unknown amounts, never an invented zero.

The net target is60% of actual company revenue, measured by an exact integer comparison. A positive month below60% is still a complete report and misses the target; target achievement never grants permission to sell. Zero and negative net remain visible. A zero-revenue month has no margin percentage or target assertion. Source evidence and supplied extra fields are not copied into output: only aggregate amounts, month, status and fixed target.

companyMonthlyMarginPresentation now turns only that internally recalculated complete report into a deterministic private envelope. Its id is `company-margin:YYYY-MM:v1`; its subject and owner-facing text are in Brazilian Portuguese, with Brazilian month names and exact `US$` formatting derived only from the completed UTC month and aggregate amounts. The function formats losses, zero revenue, exact target results and the monthly held-store aggregate without locale-dependent or floating-point arithmetic. Missing held-store observation is written as unknown, never zero. A supplied complete-looking report cannot bypass reconciliation because the function accepts the accounting input and calls companyMonthlyMarginReport itself. The result is frozen and contains no evidence, account, store, customer, address or supplied extra field.

The presentation can also receive one canonical serialized operational-observation envelope, limited to 4,096 UTF-16 characters. It accepts only schema 1, the report's exact month, an exact `storeForget` count row and a nonnegative safe `keptStarTimes` count. Duplicate JSON keys, noncanonical JSON, extra fields, another month, unsafe counts and malformed rows remain unknown. Once a caller explicitly supplies this source, `storeForgetLine` and `keptStarLine` make unknown readings visible instead of silently treating them as zero; a complete known-zero envelope emits no exception line. The input is a string, so supplied getters or Proxy traps are never traversed, and no supplied identifier or text is copied.

Tests/company-margin-report.test.ts calls this actual module and existing actual accounting validator, with synthetic records only. It checks every source/category missing, allocation mismatches, losses/zero revenue, calendar/year/leap boundaries, nonactual data, exact target edge, inaccessible getters, private-field exclusion and arithmetic overflow. Tests/company-margin-report-presentation.test.ts checks deterministic ids and words, exact target edges, losses, zero revenue, held-store unknown/aggregate wording, privacy, revoked proxies and the unchanged sales gate. These are accounting-boundary tests, not evidence of real invoices or taxes.
