# Contract reservation acknowledgement validity

AB(a), 2026-10-24. A Redis reservation can commit while the issuing admission expires, its exposure month ends, its policy changes, or the application clock moves backwards. The returned acknowledgement must revalidate the current configuration and commercial review, identical binding, admission deadline, exposure month, issuing clock and submission deadline. Otherwise no provider submission is authorized.

Refusal retains the committed cash, slot and pending lock. There is no compensating release, reset, new ledger field, Redis command or provider request. The additional local configuration/review evaluation has an unmeasured CPU cost; it is unknown, not zero. Existing per-plan monthly/annual reserves and highest-paid cost assumptions remain binding. This change does not certify a 60% margin or complete renewal/settlement coverage. Apply the more onerous treatment in docs/tax-uncertainty.md and allocate all LLC fixed costs, including preserved Hazelsong residuals, to Marktmorgen. Policies remain null, coverage flags false and PLANS_ON_SALE=false.

Synthetic regression cases advance past admission and month boundaries, roll the clock backwards, or mutate reserve evidence while awaiting a committed reservation. Each must return null and retain the exact ledger, reserved cash, occupied slot and pending lock with only the original Redis request. Existing positive activation/reservation and financial tests remain. Full remote CI on the new head is required before incorporation; no real payment or provider operation is part of verification.
