# Monthly company evidence reconciliation — MR2

This unit is a pure assembly boundary for the nine sources already defined by `COMMERCIAL_PROFIT_SOURCES`. `reconcileCompanyMonthlyEvidence` accepts one explicit complete packet per source for the previous complete UTC calendar month, all in USD, with the entire company's same-month fixed costs. It returns a detached, frozen `reconciled_actual` accounting input only when every source and category is present, all packets agree on period/currency, amounts are safe, and the allocated fixed costs equal the complete company total.

This internal Node module refuses proxies with the native `node:util.types.isProxy` check before inspecting their descriptors. The packet envelopes use exact own data descriptors; financial rows admit at most seven own scalar fields before the shared validator checks the actual financial schema and amounts. The company fixed-cost scalar must be null or a safe nonnegative integer before the accounting validator can inspect it; a nested object or Proxy is refused without traversing it, and null remains unknown. Original financial row references reach the existing `commercialProfitMix` validator before any canonical snapshot. No clone of an untrusted graph is used as a Proxy detector: such a clone could execute a getter installed by a Proxy after an earlier row was inspected. Transparent, revoked and self-detaching proxies therefore remain unknown without running their traps or getters. Extra root, packet or financial category fields are unknown; no omitted source becomes an empty source or an invented zero. Explicit evidenced zero, known losses and null-prototype own-data rows remain supported.

This boundary checks the consistency of supplied reconciliation data. It does not authenticate a provider, establish that a real invoice or ledger is complete, certify taxes or profit, or turn `complete: true` into external proof. It copies evidence only into the internal accounting dataset; it does not render or log it for the owner or customers. Owner presentation remains the separate aggregate-only report boundary.

No caller, provider ingestion, scheduler, send, key, persistent state or retention is introduced. Actual evidence remains absent; `CURRENT_COMMERCIAL_PROFIT_MIX_INPUT` remains null. Before connecting an operational collector, its commands, bytes, attempts, execution time, retention and all company costs need explicit worst-month ceilings funded before spending under MR. Unknown CI, hosting, provider and fixed costs are not zero. No sales permission, review, price, visible limit, commission, flag, gate, account, payment or external contact changes.

Validation uses the real assembler and accounting code with synthetic packets, including every omitted source/category, incomplete data, mismatched dates/currencies, unknown costs, exact fixed allocation, getters, inherited packets and hostile proxies. This is code tested in a PR, not an automatic report delivered to the owner or a customer feature.

Accessibility: no customer interface; 0 → 0 steps and decisions. No human accessibility test or certification is claimed.
