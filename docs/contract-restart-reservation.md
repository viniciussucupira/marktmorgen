# Pause restart reservation primitive

This constructs and tests only a new-term cash reservation. The real
`pauseRestart` admission coverage remains false. The TypeScript entry refuses
before Redis, including with a supplied synthetic financial review. Current
financial policies remain null. No handler or cron invokes this new action.

The same permanent contract ledger and funding configuration are reused.
A restart cannot reuse checkout (which refuses an active pointer) or switch
(which requires a currently paid period). Its source is the same subscription
and monthly plan, with an ended paid phase, matching immutable activated
binding and retained original grant receipt. It holds another full grant
against the shared cash/slot ceiling and appends the source grant identity.
Old cash, active/activated evidence and all previous receipts remain untouched.
A pending grant or a lost acknowledgement cannot reserve a second obligation.
It does not initialize a missing ledger, release money or create an expiry.

The additional raw-Lua restart branch is tested only against disposable
loopback CI Redis with synthetic receipts/cash. It does not prove that the
original subscription stopped at the provider, verify a durable pause intent,
authorize `ensurePrice` or a subscription POST, or activate a new subscription.
A full funded lifecycle still needs pre-provider durable ownership, exact
source observation, single submission, bounded read-only reconciliation of
unknown outcomes, durable provider identity and acknowledged store activation.
Old paid and legacy rights remain in their existing paths.

## Costs and limits

and internal calls; existing CI records actual INFO commandstats for first and
duplicate reservations. This is a protocol limit, not a provider invoice.
Incoming and stored restart receipts are bounded to 1024 bytes including the
source grant suffix; source activation remains bounded to256 bytes. There is
one new grant and pending reference in the same existing hash, no new key or
TTL. The source cash/receipt is retained permanently; this document does not
invent a finite free retention tail.
